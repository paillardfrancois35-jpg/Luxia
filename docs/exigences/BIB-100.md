# BIB-100 – Signaler visiblement une erreur de validation et amener sur l'onglet concerné

| Champ | Valeur |
|---|---|
| **Statut** | Réalisé |
| **Priorité** | M |
| **Phase** | P2 |
| **Source** | Test utilisateur du guide P2 (exemple 6), 2026-09-25 |
| **Remarque** | Extension de BIB-004 (validation à l'enregistrement). |
| **Liens** | BIB-004 |

## Description

> Quand une modification rend le modèle invalide (ex. deux plages qui se chevauchent), rien ne le signale sur le
> moment : il faut aller soi-même consulter l'onglet **Validation** pour s'en apercevoir. L'utilisateur ne l'a su qu'en
> y retournant volontairement pour un test.

**Comportement attendu** :
- dès qu'une erreur apparaît (ou disparaît), un indicateur visible se déclenche — au minimum un badge/pastille sur
  l'onglet **Validation** (nombre d'erreurs), éventuellement un bandeau d'alerte dans l'écran courant ;
- au moment d'**Enregistrer** alors qu'une erreur existe (déjà refusé, BIB-004), le focus doit basculer automatiquement
  sur l'onglet **Validation** pour montrer directement la liste des erreurs, sans que l'utilisateur ait à aller le
  chercher lui-même.

## Réalisation

- `src/Luxia.UI.Modules.Library/FixtureEditorViewModel.cs` : `ErrorCount`, `SelectedTabIndex`, `ValidationTabIndex`.
- `src/Luxia.UI.Modules.Library/LibraryViewModel.cs` : `Save()` bascule `SelectedTabIndex` sur l'onglet Validation quand l'enregistrement est refusé.
- `src/Luxia.UI.Modules.Library/LibraryView.axaml` : badge rouge (nombre d'erreurs) sur l'en-tête de l'onglet Validation, `TabControl.SelectedIndex` lié.
