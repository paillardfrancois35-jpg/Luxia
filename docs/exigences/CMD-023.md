# CMD-023 – Commande IdentifierAppareil

| Champ | Valeur |
|---|---|
| **Statut** | Réalisé |
| **Priorité** | — |

## Description

> Commande `IdentifierAppareil` – paramètres : appareil, actif / inactif ; module cible : Moteur.

## Réalisation

- `src/Dmx.Patch/Rules/IdentifyRules.cs` : canaux et valeurs à émettre pour rendre un appareil visible sans toucher couleur ni position.
- `src/Dmx.UI.Modules.Console/FixtureFadersViewModel.cs` : `ToggleIdentify`, blocs `AdvanceIdentify` / `StopIdentifyInternal`.

## Tests

- `Dmx.Patch.Tests/IdentifyRulesTests.cs`
- `ConsoleViewModelTests.Identify_LightsIntensityChannel_WithoutTouchingColor_AndReleasesOnStop`

| 2026-09-26 | Claude | Décision | Le catalogue place `IdentifierAppareil` « côté Moteur », mais le moteur ne calcule encore que les surcharges brutes de canaux (étape 11 de la chaîne, P0-P1) : aucun mécanisme de « clignotement minuté » n'existe côté moteur, et en créer un pour P3 aurait anticipé sur les couches et le programmeur (P4-P5). Identifier est donc réalisé comme la console elle-même : des commandes `SurchargerCanal` / `LibérerSurcharges` (CMD-020/022, déjà « Moteur ») envoyées en alternance par l'interface à un rythme fixe (400 ms), horloge réelle (comme la découverte BIB-062, pas l'horloge injectée du moteur — ce n'est pas un calcul déterministe de restitution, juste une aide visuelle de mise au point). Écart documenté ici plutôt que dans le doc 02, qui reste correct en substance : la commande passe bien par le moteur (CMD-020/022), seul le minutage est côté interface. |
